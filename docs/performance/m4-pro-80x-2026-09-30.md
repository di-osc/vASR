# M4 Pro 转写吞吐优化与准确率验证（2026-09-30）

此文件保留前轮64.80×的验收记录。后续CNN布局、im2col32及bias+GELU融合的独立对照与最新默认版本结果见[m4-pro-cnn-layout-2026-09-30.md](m4-pro-cnn-layout-2026-09-30.md)。两轮测量不得混用收益分母。

## 结论与验收状态

本轮目标为完整 call-100 的有效吞吐超过 **80 音频秒/墙钟秒**，保持识别质量。当前候选的正式中位数为 **64.80×**，**尚未达到 80×**。不改变模型权重、VAD 切分参数、参考标签、输入音频、输出长度和解码终止条件。

最终三轮和持续来流结果见下方正式验收表；没有通过验证的实验不默认开启。保留 BF16，不采用量化。CER 使用并发请求的实际输出和现有 Bench 规范化，筛选允许的最大加权 CER 增幅为绝对 0.1 个百分点，并单独检查逐条变化和 example1。实际候选的整体 CER 比基线略低。

代码已整合回当前仓库，原有未提交的数据集目录迁移保留。本报告不会把 call-200 的高原始吞吐当作达标证据，因为该语料在原版上已有大量质量异常。

## 默认启用的优化与正确性约束

1. **Metal pipeline state 缓存**：相同设备、函数与 specialization 常量共享 PSO，避免每次构造重新建立状态。设备 registry ID 进入缓存键，保留 `VASR_METAL_DISABLE_PIPELINE_CACHE` 参考路径。相同 specialization 的指针复用回归测试通过；当前模型诊断为 3 个已创建/已缓存 specialization。数学公式未改。
2. **decode 元数据**：mixed step 中纯 decode 使用现有 decode-only builder，避免每 token 重建无用的 prefill cumulative lengths。slot、block table 和跨 block context 的测试通过。
3. **压紧 prefill**：只对有效 token 执行 projection，不对整批补齐 token 做重复计算；每请求 attention 边界独立，结果按原输入顺序恢复。保留右对齐 cache causal 语义。Candle 的短查询 SDPA 路径会忽略 mask/causal，短查询有 mask 时使用明确的参考 attention。
4. **直接 paged prefill**：利用仓库已有 varlen paged attention，直接读取 KV cache，去掉全量 KV gather 和逐请求重复 dispatch。保留参考回退，KV 与 query dtype 不一致时回退，不扩大到未验证的设备/配置。
5. **已有 varlen kernel 的正确性修复**：修复 token/head pack 布局、跨请求 threadgroup 的共享 KV、维度跨步向量读取，以及缺失的 causal 限制；command encoder guard 在提交 unpack 前释放，避免锁住提交路径。新增 mixed lengths 3/70/13、cached lengths 2/7/1、GQA、head_dim 64/128 的非零 F32/BF16 比较与有限值检查。这里修复和复用已有 kernel，没有按不完整计时结论引入新的专用 attention kernel。
显式开启 paged kernel 也不能绕过 dtype eligibility：dense K/V 必须匹配 query，FP8 必须同时用于两个 cache，并提供同设备、offset=0、F32 标量 scale。公共接口还校验同设备、U32 metadata、完整连续 query、cache packing 向量宽度与 head 几何；不再吞掉 scale buffer 错误。这项审查发现的问题有失败回归和修复验证。

6. **FSMN VAD 自动走 CPU**：仅针对已验证的 M4 Pro/48 GB 默认组合。三轮持续 VAD 测量显示 CPU 比 Metal 更快，而且每条边界完全一致；显式 device 覆盖和其他 VAD 实现保持原优先级。
7. **持续来流的结果生命周期**：完成的批次独立退休；decoded chunk waveform 在解码后及时释放；producer 元数据和已消费计时记录及时清理。全局单调标识对应每批范围，拒绝过期/重复结果，未来范围等待元数据到达。streaming 不再为所有历史 chunk 扩张输出 Vec；普通 standalone finish 仍保留完整结果顺序。测试包含一个旧批次未完而 1000 个短批次完成的情况。

自动启用范围严格限定为 M4 Pro/48 GB、BF16、无 ISQ、当前 Qwen3-ASR-0.6B 结构：audio 18 层/d_model 896/out 1024，text 28 层/hidden 1024/heads 16/KV heads 8/head_dim 128。不同硬件、内存、dtype、量化或模型结构保留参考策略。现有显式覆盖仍优先：`VASR_METAL_PACKED_PREFILL=0`、`VASR_METAL_PACKED_PAGED_ATTN=0` 可分别关闭自动路径。

当前生效执行策略为 active_slots=32、decode_rows=32、mixed_step=true、prefill_wave=8、encoder_segments=8、encoder_audio_budget=120 s；安全容量独立动态估计。保持 Metal forward 锁及必要同步，不以更多 GPU workers 换吞吐。HTTP 请求/响应字段保持兼容，`perf --cer` 只新增可选报告字段。

## 各阶段诊断与剩余瓶颈

同步诊断用于定位 GPU 计算，正式 perf 不启用同步。最近一次 packed BF16 的 14 条 probe（含该服务预热计时）如下，**父子计时重叠，不能相加**：

| 阶段 | 累计时间 |
|---|---:|
| feature_extract | 0.0998 s |
| encoder_forward | 8.9780 s |
| encoder_conv_sample | 4.6573 s |
| conv1 / conv2 / conv3 | 1.8983 / 1.9700 / 0.5361 s |
| encoder_ffn | 0.7495 s |
| encoder_qkv / out projection | 0.3836 / 0.7984 s |
| encoder QK/softmax/AV | 0.9003 s |
| prefill_forward | 6.2740 s |
| decode_forward | 4.2010 s |
| decode_attention | 0.8527 s |
| decode metadata / argmax | 0.0087 / 0.0389 s |
| LM head | 0.4109 s |

CNN 约占 encoder_forward 的 52%，当前 Candle Metal Conv2d 是 im2col → GEMM → 布局恢复，第二层卷积尤其值得继续优化。已经尝试的展平 GEMM 和更大 chunk 批量没有稳定收益，不能凭微基准默认启用。下一步可研究有界跨 sample CNN 合批或 implicit convolution/MPS 路径，但尚无验证结果，也不能承诺它能达到 80×。

早期 `encoder_attention` 只记录 QK/softmax/AV，漏掉 QKV/输出投影和布局，14.9% 是局部算子占比，不能视为完整 attention 占比。现有 CLI 概览里的 prefill/decode 为 0 是旧 streaming 计数器未接入，不代表零耗时；本轮的可选 stage probe 提供有效计算测量，但尚未补齐所有阶段独立排队/锁等待、队列峰值和 Metal allocator 峰值。

先前 probe 的有效/执行 prefill token 为 13526/13526，encoder 输入 frame 为 77862/189835；CNN 按样本有效长度裁剪，不能把 frame padding 数直接解释成全都参与卷积。实际 decode 最大 32 行。

## 复现命令与结果文件

日常启动不需要用户指定并发或 encoder batch。数据迁移期间，本轮测量使用 `results/m4-pro-80x-2026-09-30/fixtures/` 下的原始快照；下面的日常数据输入路径需以迁移任务最终布局为准：

```bash
# 仓库根目录
cargo install --path vasr-transcribe --force --features metal
vasr-transcribe serve --model Qwen3-ASR-0.6B
# 另一个终端，完整预热一轮；随后重复三次正式测量
vasr-transcribe perf -i datasets/call-100 --mono true --concurrency 14 --batch-size 1 --retries 1 --cer
vasr-transcribe eval -i datasets/example1 --retries 1
```

诊断时另行设置 `VASR_METAL_STAGE_PROFILE=1 VASR_METAL_STAGE_SYNC=1`，日志筛选包含 `vasr::stage_profile=info`；不可将同步诊断结果当作正式吞吐。实验开关均默认关闭：`VASR_QWEN3_ASR_AUDIO_ATTN=project-once|grouped`、`VASR_METAL_DENSE_PROJECTION_FUSION=1`、`VASR_METAL_QUANT_BATCH_MM=1`、`VASR_METAL_CONV_FLATTEN=1`、`VASR_METAL_CONV_CHUNKS=64`、`VASR_METAL_ASR_DTYPE=f16`。跨音频 CNN 候选 `VASR_METAL_CONV_CROSS_SAMPLE=1` 以至多 64 chunks 的微批共用卷积和投影，保留每 chunk PE、尾部有效长度、样本顺序；8/32 chunks 均完成单轮筛选，没有稳定收益；默认关闭。

持续来流脚本与审计入口：

```bash
python3 docs/performance/scripts/m4_soak.py \
  --reference-perf results/m4-pro-80x-2026-09-30/final-verified-c14-b1-perf1.json \
  --output-dir results/m4-pro-80x-2026-09-30/soak \
  --server http://127.0.0.1:8867/transcribe --server-pid <服务PID> \
  --short-url /private/tmp/vasr-80x/fixtures/example1/assets/example1.mp3
python3 docs/performance/scripts/audit_soak.py \
  --baseline results/m4-pro-80x-2026-09-30/baseline-snapshot-reference.json \
  --validation-dir results/m4-pro-80x-2026-09-30 \
  --soak-dir results/m4-pro-80x-2026-09-30/soak
```

原始 JSON、数值/回归测试日志和持续响应保存至 `results/m4-pro-80x-2026-09-30/`。该目录遵循现有 results 忽略规则；本报告、候选清单和复现脚本位于可跟踪的 docs 中。性能环境变量仅记录明确的公开实验开关，不保存敏感配置。

跨音频 CNN 的初次数值测试崩溃发生在测试对空 BF16 张量做 F32 cast：Candle 零元素 cast 除零，随后 encoder 析构触发 Metal validation。修复测试空张量断言后，在 Metal validation 始终开启的条件下 CPU/F32/BF16 三项通过；没有因此关闭验证或改变计算来掩盖错误。

验收期间另一个任务继续迁移数据和 Rust 模块（包括移除 vasr-data）。上述测试/吞吐对应强制安装后冻结的 `final-guard-binary`，源文件 SHA256 保存于 `verified-source-manifest.json`，可恢复的匹配源码保存在 `verified-source/`；`unavailable.json` 列出无法匹配恢复的文件。当前工作区随后变化未重新整体编译验收，不能把冻结版本结果直接当成迁移后 checkout 的构建证明；没有覆盖另一个任务的改动。
